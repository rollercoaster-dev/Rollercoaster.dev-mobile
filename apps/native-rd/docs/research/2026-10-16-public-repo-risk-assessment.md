# Public Repo Risk Assessment — Does Staying Public Make the App Easy to Clone?

**Date:** 2026-10-16
**Status:** Research, not a decision
**Owner:** Joe

**Scope reference:** [ADR-0005 Licensing & Trademark](../decisions/ADR-0005-licensing-and-trademark.md), [App Store Launch Plan](../launch/app-store-launch-plan.md), [LICENSING.md](../../../../LICENSING.md)

**Repo facts at time of writing** (from `gh api` and `.github/`): `rollercoaster-dev/Rollercoaster.dev-mobile`, public, org Free plan, created 2026-05-14, 0 stars, 0 forks, license detected `AGPL-3.0`, `has_pages: true` (Storybook via `storybook-pages.yml`), `codeql.yml` present, `.github/dependabot.yml` present, `.coderabbit.yaml` present, one active branch ruleset (`rulez`), all 21 `runs-on:` lines are `ubuntu-latest` (no macOS runners; EAS builds run off-GitHub).

Sources marked **[secondary]** were only found in press/blog coverage, not a primary document.

## TL;DR

1. **Documented "cloned from public source and shipped first" cases exist but are rare and all involve already-viral products.** The clean example is 2048 (MIT, source on GitHub 2014-03-09; Ketchapp's ad-supported iOS clone topped the charts before Cirulli's own May 2014 app) **[secondary]**. The far larger clone wave (Wordle, Threes, Unpacking, Donut County, the 2026 vibe-coded Adobe clones) was built from screenshots and feature lists, not source. No case found of an obscure, unreleased repo being cloned pre-launch. Clone pressure tracks popularity, not repo visibility.
2. **Shipping to the store already publishes the JS.** React Native's own docs: anything in the bundle "could be accessed in plain text by anyone inspecting the app bundle". Hermes bytecode is disassembled by `hermes-dec` (listed in OWASP MASTG) and, since July 2026, decompiled to readable JavaScript with recovered control flow and Metro modules by Symbiotic's `hermes-decomp` (HBC 40–99). Public repo adds git history, tests, docs, ADRs and convenience; it does not change what is possible.
3. **AGPL gives you a clean copyright claim, not a fast one.** A clone that ships without Corresponding Source is unlicensed copying. The fast lever is the store IP form (Apple guideline 5.2 / 4.1, Google Play IP + Impersonation forms), not court. Every headline enforcement case ran 3–8 years (Hellwig v. VMware: dismissed on procedure; Neo4j v. Suhy: second Ninth Circuit appeal still pending; SFC v. Vizio: trial "late 2026" per SFC's tracker).
4. **You, as sole copyright holder, are not bound by AGPL** (GPL FAQ #DeveloperViolate), so the App Store/GPL tension that removed GNU Go (2010) and VLC (2011) does not bite the owner. Signal-iOS ships on the App Store under AGPLv3 on exactly this basis. It bites _forks_, which is a feature.
5. **Going private on org Free costs real tooling:** Pages unpublished, CodeQL off (Code Security is Team/Enterprise only), rulesets/code owners/required reviewers become unavailable (public-only on Free), Actions drop from unlimited to 2,000 min/month, CodeRabbit goes from free to $24–30/dev/month. It does not purge GH Archive, Software Heritage, Wayback or any clone already taken.
6. **Recommendation:** stay public; file the trademark (EUIPO €850 or DPMA €290) before launch; add an explicit "source-available under AGPL, brand is trademarked, impersonators will be reported" notice to the README; keep the sole-copyright invariant. Flip to private only if a concrete threat appears, and then on a paid plan, not Free.

### 1.3 Honest read

- Evidence for "public repo of an _unreleased, unknown_ app gets cloned and shipped first" is **thin to absent**. Every documented pre-emptive clone targeted something already viral (2048 web, Donut County trailer).
- AI tools reduce the cost of _reskinning_ a repo from days to hours (PearAI is the proof), but they equally reduce the cost of rebuilding from screenshots once the app is public on the store. The marginal risk from source is largest in the window _after_ the app is visible and _before_ a trademark is registered.
- With 0 stars / 0 forks, discovery risk today is near zero; the risk grows with launch publicity, which is the same moment the store copy becomes available anyway.

## 2. Does being public add risk versus being on the store?

- **The bundle is plain text by design.** React Native: "Anything included in your code could be accessed in plain text by anyone inspecting the app bundle" ([reactnative.dev/docs/security](https://reactnative.dev/docs/security)). Expo: `EXPO_PUBLIC_` values "will be visible in plain-text in your compiled application"; users can access "all of the code and embedded environment variables" ([docs.expo.dev](https://docs.expo.dev/guides/environment-variables/)).
- **Hermes bytecode is not protection.** `hermes-dec` (P1 Security) disassembles and decompiles HBC to pseudo-code; APK bundle lives at `assets/index.android.bundle` ([README](https://github.com/P1sec/hermes-dec)); OWASP lists it as [MASTG-TOOL-0104](https://mas.owasp.org/MASTG/tools/generic/MASTG-TOOL-0104/). Symbiotic Security's `hermes-decomp` (released 2026-07-23) emits readable JavaScript with recovered control flow, Metro modules rebuilt as ES modules, and identifier recovery, for HBC 40–99 ([first-party post](https://www.symbioticsec.ai/blog/hermes-bytecode-decompiler-research)).
- **What the public repo adds on top of the IPA/APK:** TypeScript types, comments, tests, Storybook, ADRs and research docs, commit history, CI config, design-token package. That is a convenience and quality delta (a cloner gets _why_, not just _what_), not a capability delta. An LLM given the decompiled bundle plus store screenshots can reconstruct most of it.
- **Net:** once shipped, visibility of the repo changes the cloner's effort by a modest constant; it does not create a new class of attacker.

## 3. AGPL-3.0: what it forbids a clone, and what enforcement looks like

Text quoted from the [OSI copy of AGPL-3.0](https://opensource.org/license/agpl-v3).

- **§6:** conveying object code (an IPA/APK) requires Corresponding Source "through the same place at no further charge" (6(d)) or one of the other 6(a)–(e) routes. A store clone with no source offer is outside the license → plain copyright infringement.
- **§5(c)/§10:** derivative must be AGPL; "You may not impose any further restrictions on the exercise of the rights granted".
- **§13:** network-interaction source offer; relevant to the future sync server, not to the phone app.
- **§8:** first-time violator who cures within 30 days of notice gets permanently reinstated; a clone that _adds_ a source link is then compliant and may stay on the store under its own name. AGPL stops proprietary clones; it does not stop _compliant_ clones. Only trademark does that (ADR-0005 already says so).
- **§7:** additional permissions are allowed; a sole copyright holder can grant an App Store exception later if forks ever need it.

**App Store tension (the owner's own shipment):**

- FSF 2010: Apple's Terms of Service "impose legal restrictions on using and distributing GNU Go", conflicting with GPLv2 §6; Apple removed the app rather than amend terms ([fsf.org](https://www.fsf.org/news/2010-05-app-store-compliance)).
- VLC was pulled in January 2011 after Rémi Denis-Courmont's notice **[secondary]** ([TNW](https://thenextweb.com/news/apple-officially-pulls-vlc-from-the-app-store)); VLC-iOS is now "under the GPLv2 (or later) and the MPLv2 license" ([videolan/vlc-ios README](https://github.com/videolan/vlc-ios)).
- GPL FAQ, retrieved 2026-10-16: "the GPL is a license from the developer for others to use, distribute and change the program. The developer itself is not bound by it, so no matter what the developer does, this is not a 'violation' of the GPL" ([#DeveloperViolate](https://www.gnu.org/licenses/gpl-faq.html#DeveloperViolate)). Also: "The GPL does not require you to release your modified version, or any part of it" ([#GPLRequireSourcePostedPublic](https://www.gnu.org/licenses/gpl-faq.html#GPLRequireSourcePostedPublic)).
- Precedent: [Signal-iOS `LICENSE`](https://raw.githubusercontent.com/signalapp/Signal-iOS/main/LICENSE) is AGPLv3 and the app is on the App Store, because the sole distributor is the copyright holder.
- **Condition:** this only holds while the sole-copyright invariant in ADR-0005 holds. A DCO sign-off certifies origin; it does **not** assign copyright or grant relicensing rights ([developercertificate.org](https://developercertificate.org/)). Any merged outside contribution to `apps/native-rd` makes that contributor an AGPL licensor to you, and the App Store exception question becomes real. Either keep contributions to the Apache/MIT packages, use a CLA for the app, or add a §7 App Store additional permission before the first external PR lands.

## 4. Trademark and brand, independent of code

- **ADR-0005** (accepted 2026-05-14) already names App Store impersonators as the top threat and prescribes: ™ immediately, EUIPO registration (classes 9 + 42) before meaningful store presence, DPMA/EUIPO prior-art search, and the sole-copyright invariant. It states plainly: "No license choice prevents App Store impersonators; only trademark complaints get them removed."
- **Fees:** DPMA e-filing €290 incl. up to three classes, €100 per class from the fourth ([dpma.de](https://www.dpma.de/service/gebuehren/marken/index.html)). EUIPO: €850 one class e-filing, +€50 second class, +€150 per further class — figures from the EUTMR Annex I as reported by practitioner guides **[secondary; EUIPO fee page returned 403 on fetch]** ([Finnegan](https://www.finnegan.com/en/insights/ip-updates/major-changes-in-european-trademark-practice-coming-march-23.html)).
- **Store hooks that need no registration but work better with one:** Apple 4.1(b) "Submitting apps which impersonate other apps or services is considered a violation of the Developer Code of Conduct", 4.1(c) "You cannot use another developer's icon, brand, or product name", 5.2.1 "Apps should be submitted by the person or legal entity that owns or has licensed the intellectual property" ([guidelines](https://developer.apple.com/app-store/review/guidelines/)). Google Play: separate trademark/copyright [report form](https://support.google.com/googleplay/android-developer/contact/policy_violation_report) and an [Impersonation policy](https://support.google.com/googleplay/android-developer/answer/16341334) for non-IP-holder reports.
- **What it protects:** name, logo, app title in store search. It does not protect the UX concept, the ND-first design or the feature set — nothing does, public or private.

**What going private does not undo:**

- Forks "will remain public and will be detached" (none exist today); "Stars and watchers ... will be erased" (none today); "GitHub will no longer include the repository in the GitHub Archive Program" — future only ([visibility docs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)).

## Bottom line

- Public source is not the thing that makes cloning easy; the shipped Hermes bundle already is, and 2026 decompilers turn it back into readable JavaScript. The repo's marginal contribution to clone risk is convenience, not capability.
- No documented case of an unknown, unreleased repo being cloned and shipped first; every real incident targeted something already popular. With 0 stars / 0 forks, discovery risk is negligible until launch, when the store copy exists anyway.
- AGPL plus the Apple 5.2 / Google Play IP forms is the practical defence against a proprietary clone; the trademark is the only defence against a _compliant_ clone using the name. File it before launch (DPMA €290 or EUIPO ~€850).
- Flipping to private on org Free loses Pages, CodeQL, rulesets/required reviewers, free CodeRabbit and unlimited Actions, and recovers nothing from GH Archive, Software Heritage or Wayback. If privacy is ever chosen, do it on Team, not Free.
- The one real licensing gap: the DCO does not give relicensing rights. Decide (CLA for `apps/native-rd`, or a §7 App Store additional permission) before the first outside contribution lands.
- Recommendation: stay public (Option A + D), add the trademark/source-available notice to the README, file the mark, and revisit only on a concrete signal (a fork that ships, a store listing using the name).
