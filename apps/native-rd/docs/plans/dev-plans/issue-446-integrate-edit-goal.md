# Development Plan: Issue #446

## Issue Summary

**Title**: [Integrate] Edit Goal — mount the editor, wire Focus ✎ + Timeline Edit ›
**Type**: feature (integration — wiring only, no new presentational UI)
**Complexity**: MEDIUM
**Estimated Lines**: ~380 lines (≈180 implementation, ≈100 i18n JSON en+de, ≈100 test delta)

## Intent Verification

- [x] Tapping the Focus Mode header ✎ or Timeline's "Edit ›" opens the redesigned `EditGoalView` (drag-reorderable rows, evidence chips, ⋯ overflow menu) — the old `StepList`-based layout is no longer reachable from either entry point.
- [x] Editing the goal title or description persists via the existing debounced `updateGoal` mutation (500ms), same as before — verified by the existing debounce tests continuing to pass against the new container.
- [x] Adding, renaming, reordering, reparenting, and deleting a step or sub-step (with the `ConfirmDeleteModal` confirm step) all persist through Evolu and are reflected in `useQuery(stepsByGoalQuery(...))` on the next render.
- [x] A step that has `afterStepId`, `waitingOnLabel`/`waitingOnExpectedAt`, or `dueAt` set renders the matching chip(s) (`after`, `waiting`, `due`) on its row; a step with none of those columns set renders no chip row at all (never a "no due date" placeholder).
- [x] The ⋯ menu opens a popover containing only "Delete goal"; confirming routes through the same `ConfirmDeleteModal` copy/flow the old screen used, and a successful delete navigates to `Goals`.
- [x] "Done" (the new footer button, replacing the old "Start Working" / "Back to Focus" button) returns the user to Focus Mode on this goal, matching Edit Goal Flow C — for both entry points (Focus ✎ and Timeline "Edit ›").

## Objective

Replace `EditModeScreen`'s current hand-built `StepList`-based body with the storied `EditGoalView`, wiring its ~20 callback props to the same Evolu mutations (`updateGoal`, `updateStep`, `createStep`, `createSubStep`, `deleteStep`, `deleteGoal`, `reorderSteps`, `reorderSubSteps`) the old screen already used, plus mapping `resolveStepDependencyBand` into `EditGoalDateDepChip[]`. Both entry points (Focus ✎, Timeline "Edit ›") already navigate to the `EditMode` route, so this is a pure container-internals swap — no `navigation/types.ts` or stack changes.

## Discovery Log

- [2026-08-07] **D11 (new) — `dragScrollController` could not be wired as planned.** Step 1's "confirm `EditGoalView`'s own internal `ScrollView` is the one the controller measures" resolves to _no_: the container has no way to attach `ref`/`onLayout`/`onScroll`/`onContentSizeChange` to a `ScrollView` that `EditGoalView` owns. Passing the controller anyway would have been dead wiring — with all-zero metrics `getAutoScrollVelocity` returns 0 for every pointer position, silently disabling edge auto-scroll that the old screen had. Fix: one optional `scrollInstrumentation` prop on `EditGoalView` (`{ ref, onLayout, onScroll, onContentSizeChange }`), forwarded to its internal `ScrollView`. No visual or UI change; Storybook omits it. Also dropped the old `scrollEnabled={!isStepDragging}` toggle — `EditGoalStepList` exposes no drag-state callback, and the storied editor already behaves this way.
- [2026-08-07] **Title errors move from inline text to `Alert`.** `EditGoalView`'s title card has no error slot, and adding one would be un-storied UI (explicitly forbidden by the acceptance criteria). Both the empty-title guard (`errors.titleRequired`) and the write failure (`errors.updateTitleFailed`) now surface through `Alert`, the same channel the description path has always used. `titleError` state is gone.
- [2026-08-07] **Container split into three modules** to stay near the pre-existing file-size warning (587 lines before → 533 after, vs. 662 when everything lived inline): `editGoalCopy.ts` (the ~30 `t()`-resolved copy props) and `editGoalSteps.ts` (DB rows → `EditGoalStep[]` incl. the D6 chip mapping) alongside `EditModeScreen.tsx`.
- [2026-08-07] **`cameFromFocus` route param removed.** "Done" replaces both "Start Working" and "Back to Focus" and always returns to Focus Mode, so the flag had no remaining reader. Dropped from `navigation/types.ts`, `FocusModeScreen`'s navigate call, and a now-false comment in `TimelineJourneyScreen`. (The plan said these files needed no changes — this is the one exception, caused directly by the button swap.)
- [2026-08-07] **i18n keys reused rather than duplicated.** Most of `EditGoalView`'s copy props map onto keys the old screen already had (`stepList.header`, `count`, `addPlaceholder`, `addButtonA11y`, `evidenceTypesLabel`, `addSubStepLabel`, the whole `stepList.a11y.nestUnder*` family, `common:actions.close`/`cancel`). Genuinely new: `editor.*`, `confirmDeleteStep.*`, `confirmDeleteSubStep.*`, `stepList.dateDepChips.*`, and three title-bearing announcement keys (`a11y.movedToPosition`, `a11y.stepPromotedToTopLevel`, `a11y.stepNestedUnder` — the existing `movedUp`/`nestedUnder`/`promotedToTopLevel` keys don't carry the same placeholders). Removed: `actions.backToFocus`, `actions.startWorking`.
- [2026-08-07] **Commits grouped 3-for-5.** Plan steps 1–3 all rewrite the same regions of `EditModeScreen.tsx`, so they landed as one `feat` commit; i18n and tests kept their own.
