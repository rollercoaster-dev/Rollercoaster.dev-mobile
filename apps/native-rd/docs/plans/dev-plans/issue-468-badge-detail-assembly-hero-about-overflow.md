## Discovery Log

- [2026-08-07] **Steps 1+2 merged into one commit.** Shipping the hero without the menu would have left the `⋯` button a dead tap for one commit, contradicting the plan's own "no dead taps" intent criterion. Step 4's test changes were also folded into the commits that changed the behavior they cover, rather than deferred — otherwise commit 1 would have shipped with a red suite (the old `"L"` initial-fallback and `Badge image for …` tests assert markup the hero replaces). Net: 2 commits, both green, instead of 4.
- [2026-08-07] **Hero placed inside the ScrollView, not above it.** The plan left this open ("above the ScrollView … or ListHeaderComponent-equivalent"). A pinned hero costs ~350pt of a phone screen permanently; the prototype scrolls it. This required moving `paddingHorizontal` off `scrollContent` onto a new `body` wrapper so the band runs full-bleed — the source of most of the diff's line churn (re-indentation).
- [2026-08-07] **`hero.credentialLabelUndated` added beyond the two keys the plan listed.** `formatDate` returns `""` (not null) for a missing date, so the templated label would have rendered "Verifiable · earned " with nothing after it. A credentialed-but-undated badge now gets a bare "Verifiable".
- [2026-08-07] **Dead i18n keys removed.** `identityA11y.*` (identity chip) and `image.a11y` (floating-preview `Image`) had no remaining callers. `locale-parity.test.ts` enforces en↔pseudo parity, so these were dropped from `en` + `de` and pseudo was regenerated. `de` is otherwise left to CI sync.
- [2026-08-07] **`imageLoadFailed` state retired.** It only existed to catch `onError` on the preview `Image`, which no longer renders; `hasRealImage` (still gating the export buttons) is now a pure derivation of `imageUri`.
- [2026-08-07] Unrelated pre-existing pseudo-locale drift in `completion.json` / `editGoal.json` surfaced on `bun run gen:pseudo` and was reverted rather than folded into this PR.
