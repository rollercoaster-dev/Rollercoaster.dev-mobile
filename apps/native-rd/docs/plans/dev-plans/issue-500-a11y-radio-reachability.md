## Objective

Stop `ThemeSwatchRail` and `SettingsDensityRows` from collapsing their radio children into a single VoiceOver/TalkBack node in production, by removing the `accessible={true}` wrapper (and the `EXPO_PUBLIC_E2E_MODE` branch that only worked around it in E2E builds). Compose the density description into each row's accessible name, and localize the one remaining hardcoded English group label (`ThemeSwatchRail`'s "Theme selection").

## Discovery Log

- [2026-08-07] **D2 confirmed, with a caveat on the inverse assertion.** `getByLabelText(...).props.accessibilityRole` works as the plan predicted. But RNTL's `{ name }` filter also matches an element's _descendant text_, not just its `accessibilityLabel` — so `queryByRole("radio", { name: "Compact" })` still resolves a row whose accessible name is `"Compact. Tighter spacing (0.75×)"`, via the visible `<Text>Compact</Text>` inside it. Tests that need to prove an override took effect must assert `props.accessibilityLabel` directly rather than assert the un-overridden name is absent.
- [2026-08-07] **Pseudo-locale `changeLanguage` needs `act()` here.** `AudioPlayer.test.tsx`'s bare `await i18n.changeLanguage(...)` emits no warning, but the same call in `ThemeSwatchRail.test.tsx` does — `renderWithProviders` keeps a subscribed tree mounted across the language switch. Both the switch to `"pseudo"` and the `afterEach` revert are wrapped in `act()`.
- [2026-08-07] **`bun run gen:pseudo` surfaced pre-existing drift in three unrelated namespaces.** Regenerating rewrote padding-dot runs in `pseudo/badgeDetail.json`, `pseudo/completion.json`, and `pseudo/editGoal.json` — checked-in output that predates this branch and is stale relative to the current `pseudoTransform`. Reverted those three to keep this PR's diff to `pseudo/common.json`; worth a follow-up sweep (or a CI check that `gen:pseudo` is a no-op).
- [2026-08-07] **`densityA11yLabel` resolves against `settings`, not `common`.** Unlike every existing helper in `src/i18n/labels.ts`, the density strings live in the `settings` namespace, so the file now carries a second `SETTINGS_NS` const and its header comment no longer claims to be common-only.
- [2026-08-07] **On-device a11y tree verified with Maestro on the iOS Simulator.** VoiceOver does not run in the Simulator, so instead of "listening" the tree itself was dumped (`maestro hierarchy`) against Storybook, `EXPO_PUBLIC_E2E_MODE` unset. Maestro 2.8.0 installed per `e2e/README.md` (`mobile-dev-inc/tap/maestro` — NOT `brew install maestro`). Results below are from `h_rail.json` / `h_density.json`.
  - **`ThemeSwatchRail` — criterion 1 PASSES.** All 7 swatches appear as separate elements, each labelled `"<name>. <description>"` (e.g. `'Bold Ink. High contrast (WCAG AAA)'`). Role and state come through iOS's `value` field: selected → `"radio button, checked"`, others → `"radio button, unchecked"`. Pre-fix this collapsed to one node.
  - **`SettingsDensityRows` — criterion 2 PASSES.** All 3 rows separate, labelled `'Compact. Tighter spacing (0.75×)'` / `'Default. Standard spacing'` / `'Comfortable. Roomier spacing (1.25×)'`, with `value` = `"radio button, checked"` on Default and `"unchecked"` on the other two. This confirms D4's composite label reaches the platform, which Jest could only assert against a mock.
  - **Criterion 4 PASSES by construction** — no `EXPO_PUBLIC_E2E_MODE` read remains in either component (only a comment mentions it), so there is no prod/E2E tree to diverge.
- [2026-08-07] **Criterion 3 does NOT hold on iOS — the rail's group label never reaches the a11y tree.** `theme.picker.groupLabel` ("Theme") appears **zero** times in the dumped hierarchy. Without `accessible`, iOS does not materialise the wrapper as an accessibility element, so its `accessibilityRole="radiogroup"` + `accessibilityLabel` are inert there — VoiceOver will announce the 7 swatches but never "Theme, radio group". The Jest test passes because RNTL reads the React props, not the platform tree; it proves the string is routed through i18n (the real point of D3), not that iOS speaks it. **This is inherent to D1, not a coding error:** `accessible` is exactly what would surface the group, and it is also exactly what collapses the children. The issue's own framing treats these as independent; they are not. Notably `SettingsDensityRows` _does_ surface its group (`'Content Density'`, bounds `[16,100][386,250]`, wrapping all 3 rows) — the asymmetry is that the rail's wrapper has a `ScrollView` as its only child. Worth a follow-up if the group name matters: put the label on a real element, or accept per-radio labels as the whole contract (which is what the shipped badge selectors do).
