## Intent Verification

- [x] A step whose DB `status` is `paused` renders its node/pill in the shared purple "paused" color (`stepStateColorMap.paused`) — not the "pending" color it silently renders today.
- [x] A `paused` step is never selected as the journey's single `in-progress` accent, even when it is the first non-completed row in its group (mirrors `resolveNextActionableStep`'s skip-paused rule already live in FocusMode).
- [x] The header shows "N done · N in motion · N to come · N set aside" (via `TimelineBreakdownBar`) instead of "X of Y steps completed"; a goal with zero paused steps shows no "0 set aside" chip; the four counts sum to `stepRows.length` (parents + substeps, per the existing every-unit rule).

- [x] Tapping "Edit ›" in the header navigates to `EditMode` for this goal.
- [x] `bun run test --testPathPatterns TimelineJourneyScreen` is green (34 tests); full suite 213 suites / 10008 tests green; `bun run type-check` clean; `bun run lint` 0 errors.

## Discovery Log

- [2026-07-24] **`progressContainer` was renamed, not deleted (Step 2 deviation).** The plan said to drop `progressContainer`/`progressLabel` outright, but `TimelineBreakdownBar`'s `card` style carries no outer margin of its own — deleting the wrapper butted the bar straight against the goal title/description. `progressContainer` is therefore renamed to `breakdownContainer` (same `marginTop: theme.space[3]`) and kept as a spacing-only wrapper; `progressLabel` is gone as planned.
- [2026-07-24] **The C·B band's connective copy is still hardcoded English.** Step 3 wires the _data_ (`afterStepId` → `afterStep`, `waitingOnLabel`/`waitingOnExpectedAt` → `waitingOn`, `dueAt` → `dueDate`, dates through `formatDate(x, i18n.language)`), so the dates localise. But `MetadataBand` in `TimelineStep.tsx:268-275` still builds its lines from literal `` `after ${…}` `` / `` `waiting on ${…} · expected ${…}` `` / `` `due ${…}` `` template strings. `TimelineStep.tsx:256-257` names #378 as the owner of "real data + i18n", while this plan's Affected Areas explicitly scoped `TimelineStep.tsx` to _no changes_ — the two disagree. Implemented per the plan (data only); the i18n half is listed under Follow-ups below rather than silently absorbed.
- [2026-07-24] **`local/file-size-limit` warning grew, not introduced.** `TimelineJourneyScreen.tsx` was already 323 lines (limit 300) before this work and is now 362. Warning only, `bun run lint` still reports 0 errors. Splitting the screen was out of scope for a wiring-only issue.
- [2026-07-25] **The band's connective copy is now localized (follow-up closed in this PR).** Four whole-sentence keys under `timelineJourney:step.metadata.*` — `after`, `waitingOn`, `waitingOnExpected`, `due` — in en/de/pseudo, built with `t()` inside `MetadataBand`. Waiting-on is two full keys, not one key plus an "· expected …" suffix, so a translator can reorder who-vs-date (docs/i18n.md "Don't concatenate translated fragments"). En copy is byte-identical to the old literals, so the existing band assertions still read as English; a new pseudo-locale `it.each` block covers all four lines as the regression net. Dates still arrive pre-formatted from the screen via `formatDate(x, i18n.language)` — the keys only wrap them. `MetadataBand` moved to a new `TimelineStep.parts.tsx` (the `FocusCurrentTaskCard.parts.tsx` convention) because the `t()` calls pushed `TimelineStep.tsx` past the 300-line `local/file-size-limit`; lint is back to its 222-warning baseline, still 0 errors.
- [2026-07-24] **Test-mock convention extended.** The `db` mock now carries faithful copies of `resolveNextActionableStep` _and_ `resolveStepDependencyBand` (matching the existing `groupStepsByParent`/`areAllStepsComplete` convention), so the accent, breakdown buckets, and C·B band all run against real resolution rules rather than stubs. Band-date assertions use a local-noon ISO (`2026-01-28T12:00:00`, no `Z`) so they don't depend on the runner's timezone — the same guard `utils/__tests__/format.test.ts` uses.
