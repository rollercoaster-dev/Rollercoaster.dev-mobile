## Issue Summary

**Type**: enhancement
**Complexity**: MEDIUM

## Intent Verification

- [x] When a user pins a goal, that goal renders as the `GoalsCockpit` hero on the next Goals-tab visit and across app restarts (persisted in `userSettings.pinnedGoalId`).
- [x] When a user pins goal B while goal A is already pinned, goal A returns to being a normal "keep warm" card (or drops off the hero entirely) and only goal B is pinned — never two.
- [x] When a user unpins the current hero, the hero reverts to the #381 default (most-recently-worked active goal) on the very next render — no stale pin.
- [x] If the pinned goal is completed or deleted (so it no longer appears in `activeGoalsQuery`), the cockpit silently falls back to the most-recently-worked default instead of showing an empty hero or throwing.
- [x] Every cockpit goal tile (hero + keep-warm) shows a pin icon whose active/inactive state matches whether that goal is pinned, and tapping it toggles the pin — active → unpinned, inactive → pinned.
- [x] The same toggle exists in the goal's FocusMode header and stays in sync with the cockpit (both read `userSettings.pinnedGoalId`).
- [x] Each pin control is an `IconButton` with an `accessibilityLabel`, `accessibilityState={{ selected }}`, and a hit target ≥44×44pt (verified via `IconButton`'s existing `sizeValues`/`hitSlop`).

## Objective

Let a user override the #381 default cockpit hero (most-recently-worked active goal) by pinning a specific goal. A pin always wins the hero slot; pinning a new goal replaces the old pin (single cockpit slot, enforced structurally, not by convention); unpinning returns to the default; the pin persists across sessions via Evolu/`userSettings`.

## Discovery Log

- [2026-08-09] **Step order changed.** i18n (planned Step 5) landed second, ahead of the UI steps, so every commit that references a key is self-contained and its tests resolve real strings. Step 2 was narrowed to hero resolution only; the pin handlers moved into Step 3 with the cockpit props they feed — splitting them would have left either unused handlers (lint) or unknown props (typecheck) in an intermediate commit.
- [2026-08-09] **`IconButton` gained `selected` + `accessibilityHint` props.** The component hard-coded `accessibilityState={{ disabled }}` and had no hint prop, so D4's `accessibilityState={{ selected }}` requirement was unreachable from a call site. Both are optional and `undefined` by default, so every existing call site is unchanged.
- [2026-08-09] **Pin state is carried by icon weight, not color (deviation from D4).** `IconButton` owns icon color per tone by design (`resolveIconColor` lives in the styles module precisely so call sites never pass a token), so the planned "accent when pinned" was not available without breaking that boundary. `weight="fill"` vs `"regular"` plus `accessibilityState.selected` and the label swap carry the state instead — and a weight-only change is the calmer option under autismFriendly/lowInfo anyway.
- [2026-08-09] **Sentry context is `{ area: "settings.pin" }`, not `{ area: "goal.mutate", kind: "pin" }`.** `goal.mutate`'s `kind` is a closed enum with no `pin` member, and the write targets `userSettings`, not `goal` — so it belongs beside the existing `settings.density` / `settings.theme` areas. Added one variant to `ReportContext`.
- [2026-08-09] **Two error-copy keys added beyond the planned set.** `goals:pinError.*` (Alert, matching the cockpit's `deleteError` shape) and `focusMode:errors.couldNotChangePin` (toast, matching that screen's own failure convention — FocusMode uses toasts, not Alerts).
- [2026-08-09] **Keep-warm pin sits in-flow, not absolute.** The tile title is `numberOfLines={1}` at full width; an absolutely-positioned corner pin would run underneath it. Title and pin now share a `keepWarmHeader` row so the title shrinks around the control. The hero pin is absolute as planned — its stack is centred and the top-right corner is free.
- [2026-08-09] **Reversed by self-review: the keep-warm pin is absolute after all, and outside the tile `Pressable`.** The in-flow arrangement above put the pin inside a `Pressable` marked `accessible`, which collapses its whole subtree into one screen-reader node — the pin was unreachable to VoiceOver/TalkBack entirely. It is now an absolutely-positioned sibling of the card (`keepWarmCell` owns the grid width), matching the hero, with `paddingRight` on the title reserving the corner so a long title still truncates before it. The original test passed either way because `getByTestId` reads the element tree rather than the a11y tree; the replacement asserts the pin is not a descendant of the collapsed node.
- [2026-08-09] **`IconButton.hitSlop` was inert.** It was set inside the object returned by `styles.pressable(size)`, but `hitSlop` is a `Pressable` prop, not a style — so every `size="sm"` button, including all three new pin controls, rendered a bare 36pt target against the 44pt guideline. Now passed as a prop. Pre-existing app-wide bug, fixed here because this issue's own plan claimed ≥44pt was verified through it.
- [2026-08-09] **Pin breadcrumbs moved to a new `settings` category.** `pinGoal`/`unpinGoal` initially emitted `category: "goal", message: "update"`, which planted a phantom "goal updated" crumb ahead of unrelated `goal.mutate` errors — and contradicted the `settings.pin` reasoning two entries up.
