# Development Plan: Issue #469

## Issue Summary

**Title**: [Integrate] Badge Detail assembly 2/2 — proof spine + Share sheet + Delete demotion
**Type**: feature (integration/wiring — no new presentational components)
**Complexity**: MEDIUM
**Estimated Lines**: ~450 lines (issue's own estimate: 450–600 LOC)

## Intent Verification

- [x] When a user opens Badge Detail for a badge with evidence in its credential, the screen renders `ProofSpine` as a horizontally-swipeable gallery directly below the hero, fed from `extractEvidenceItems(credential)` — not live DB evidence rows — so it still renders correctly if the goal/step is later edited or the goal is soft-deleted.
- [x] When a user taps a proof card, the app navigates to `EvidenceViewer` (`GoalsTab`) landed on that exact evidence item — not just "some" item — because the credential's `urn:ulid:`-prefixed id is stripped back to the raw ULID `useAllEvidenceForGoal` matches on.
- [x] When a badge's goal is soft-deleted (`goalId` is null), tapping a proof card does not throw or navigate anywhere broken — it no-ops safely, the same way "View timeline" already hides for this case.
- [x] When a user taps "Share badge" (either the new on-page primary CTA or the overflow row), the same `BadgeShareSheet` opens with the three export rows correctly enabled/disabled from `hasRealImage`/`badge.credential`, and each row calls the real `useBadgeExport()` function it's supposed to.
- [x] When a user wants to delete a badge, the standalone full-width destructive button is gone from the page; Delete is reachable only via the `⋯` overflow row, and confirming shows the reframed copy ("Delete this badge? ... Your goal and its evidence stay in the timeline — only the credential artifact is deleted.") with "Keep it" / "Delete" buttons.
- [x] When a badge has no evidence in its credential, `ProofSpine` shows its own honest "nothing to show in the gallery" card (already built by #411) — the screen does not additionally render a "missing"/"needed" prompt anywhere else.

## Discovery Log

- [2026-08-09] **Step 4 folded into Steps 1-3.** The plan's separate test-rewrite commit would have left the screen suite red across two intermediate commits (the a11y-label and delete-trigger assertions break the moment the JSX changes). Each step now ships its own test changes, so every commit on the branch is green on its own. Commit count: 3 planned + 1 small i18n cleanup, instead of 4.
- [2026-08-09] **`BadgeShareSheet` hoisted out of the `ScrollView` (D14).** Discovered while wiring Step 2: `AnimatedSheet` is an in-tree absolute overlay, so mounting it in scroll content anchors the sheet to the content's bottom rather than the viewport. Mounted as a root-level sibling instead (`ScrollView` gains `flex: 1`), which makes the Share CTA a pinned footer above the tab bar rather than an in-page block. Added an optional layout-only `ctaStyle` prop so the CTA keeps the body's gutter. **Worth a look on device** — the prototype has the CTA in-page; this is the correct-anchoring trade.
- [2026-08-09] **Narrative block moved out of the About/Details `Card` (D3 as written).** It now renders as a bare `infoBlock` above `ProofSpine`, so the "How it was earned" sentence sits with the proof it describes instead of inside the details card.
- [2026-08-09] `common:evidenceTypes.text.label` is **"Note"**, not "Text" — caught by a failing proof-card navigation test asserting the wrong a11y label.
- [2026-08-09] **D12's "CI syncs `de/`" premise is only half true.** `i18n-sync.yml` fills keys that are _missing_ from `de/`, but `collectMissing` skips any leaf the target already has (so a **changed** `en` value is never re-translated) and `fillMissing` copies target-only keys through rather than pruning them (`jsonTreeUtils.ts:164,184`). Both halves of this slice's `de/` drift — the reframed `deleteConfirm` copy and the 8 retired keys — sat in that blind spot and would have persisted indefinitely. Fix: delete the stale `de/` values so the sync sees them as gaps and regenerates them through the register + glossary; prune the retired keys by hand. **Future slices that change existing `en` copy must do the same** — "CI handles it" applies to new keys only.
