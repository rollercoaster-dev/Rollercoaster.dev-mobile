## Intent Verification

- [ ] Tapping "Design your badge →" from Focus Mode's all-complete state (`FocusModeScreen.tsx:497-499`) or Timeline's `FinishLine` CTA (`TimelineJourneyScreen.tsx:216`) lands on the redesigned `FinishCelebrateStage` — never the old `CompletionFlowScreen` evidence-prompt/celebration UI.
- [ ] From celebrate, pressing "Design your badge →" shows `FinishDesignStage` seeded with the goal's existing `design` (or a default); editing any accordion section and pressing "Bake my badge" captures that exact edited design (not a stale default) and transitions to `FinishBakingStage`.
- [ ] While baking, `FinishBakingStage`'s `status` prop tracks `useCreateBadge`'s live status end-to-end: a real signing-key failure renders `no-key` with a working "Continue without a badge" exit; a real pipeline throw renders `error` with a working Retry that visibly returns to a busy state before ever showing a repeat error (no stuck-disabled Retry).
- [ ] On a real successful bake, `FinishRevealStage` shows the actual baked badge, the actual goal title, and an actual formatted earned date (from `goal.completedAt`) — then "View badge" navigates to the real `BadgeDetail` screen for that badge, and "Back to goals" returns to the Goals list with the stack cleared.
- [ ] The tab bar is not visible anywhere in the celebrate → design → baking → reveal sequence (matches `App Shell.dc.html`'s `showTab` exclusion of the `finish` route), and reappears normally once the user exits.
- [ ] `grep -rn "BadgeEarnedModal\|CompletionFlowScreen" src` (excluding this plan and the dev-plans directory) returns no matches once this PR lands — both are fully retired, not left as dead-but-reachable code.
- [ ] `grep -rn "\"CompletionFlow\"" src/screens src/navigation` still finds exactly the `GoalsStack` route registration and the two entry-point `navigate()` calls — zero routing/param changes at either call site (D4 from #447 holds).

## Objective

Retire `CompletionFlowScreen` and `BadgeEarnedModal` in favor of the already-built, already-storied `FinishCelebrateStage` → `FinishDesignStage` → `FinishBakingStage` → `FinishRevealStage` sequence, wired to the real `useCreateBadge`/`useUserKey` pipeline and real navigation. Both existing entry points (`FocusModeScreen`'s all-complete CTA, `FinishLine`'s CTA in `TimelineJourneyScreen`) keep navigating to the same `CompletionFlow` route with the same `{ goalId }` param — only the screen behind that route changes. Signing/baking logic in `useCreateBadge`/`openbadges-core` is untouched; this issue only changes the surface.
